The operator clarified that the workers are external runtimes: OMP over ACP or Durable Agents in Cloudflare. My proposed planner/coder/reviewer Hermes profiles did not match that architecture.

Hermes' worker-lane reference explicitly says a non-Hermes CLI lane is not yet a paved path. Launching, mapping workspaces and reporting lifecycle outcomes remain integration work; a pluggable spawn function is not a ready OMP or Cloudflare connector.

Hermes' MCP guide recommends MCP for local or remote systems behind an RPC interface, and a narrow native tool when that is simpler. This provides an extension point for an external-agent control interface, not the implementation of that interface.

The earlier inherited-toolset explanation concerns tools exposed by Hermes child instances. It must not be used to infer the permissions of an independently configured external worker.

Sources: [External Kanban worker lanes](https://hermes-agent.nousresearch.com/docs/user-guide/features/kanban-worker-lanes#adding-an-external-cli-worker-lane), [When to use MCP](https://hermes-agent.nousresearch.com/docs/guides/use-mcp-with-hermes#when-should-you-use-mcp).
